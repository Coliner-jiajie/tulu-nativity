## 1. DQN 路线（F1~F4）

### 做了什么
- 专家：滚动前瞻（R=200），对每个决策状态的每个候选动作记录「剩余回报」，得到 36 维 Q 向量（未评估的动作为 NaN）。共 5 万余局的数据，约 77 万条，其中约一半的决策状态有 ≥2 个被评估的候选。
- 网络：决斗式 Q 网络（512×3）。
- 离线：Q 回归 + 优势项 + 间隔损失（DQfD 风格），再加一版监督项。
- 在线：Double DQN、n 步回报（8）、ε 从 0.05 降到 0.01、混入专家数据、目标网络软更新。

### 结果
| 阶段 | 2 万局贪心评估 |
|---|---|
| 离线 Q 回归（qbig_net） | 1204.4 |
| 离线 Q + 监督项（qbig_ce） | 1237.0 |
| 在线 DQN 起点 | 1236.1 ± 0.8 |
| 在线 DQN 第 100 步 | 1229.9（之后一路更差，到 1219~1231，未保存） |
| 对照：BC 1267，PPO 微调 ft3 1295.8，专家约 1288 | |

数据本身没有问题：专家生成的局平均 1285~1290，和之前的专家水平一致（`archive/failed_dqn/big.log`）。

### 原因分析
1. **目标定义错误（已修复，【已验证】）**：滚动前瞻给的是整局总倍率，包含该状态之前已经累计的部分。网络看不到历史，直接回归会发散。减去「已累计倍率」后改成「剩余回报」，最优候选的 Q 与真实剩余回报的相关系数达 0.978，训练才稳定。这是 F1 之前的一个更低分阶段的原因。
2. **回归的精度要求与问题不匹配（【推测】，间接证据）**：同一状态下，最优与次优候选的差距只有几分，而单局的随机波动约 ±100（p5~p95 约 1056~1417）。要靠价值回归把相对排序学对，需要的精度远高于分类式方法。间接证据：回归损失（约 7500~8200）远大于动作间差距，验证集上「与专家一致率」只有 0.48~0.51；而 BC 是直接学「选哪个」，同样数据下得到 1267。
3. **未评估动作被高估（【推测】，间接证据）**：只有约一半的状态评估了多个候选，其余候选的 Q 是 NaN，网络对它们靠外推。贪心时一旦选到外推出来的高估动作就吃亏。加监督项让网络贴近专家选择后从 1204 升到 1237，说明约束「选择」比拟合「数值」有效。
4. **在线 TD 更新破坏已有排序（【推测】）**：自举目标带噪声，起点 1236 在微调后每次评估都更低，且 loss 几乎不下降（约 0.21~0.23）。可能是 ε 探索产生的数据分布与评估时的贪心分布不一致，也可能是学习率仍偏大。没有做专门的消融去区分。
5. **欠训练（F4，【已验证】）**：试点只有 7.7 万条样本，离线 Q 只有 887.6，连贪心（1156）都不如，说明这类方法对数据量很敏感。

### 教训
- 对「动作间差距小、噪声大」的问题，优先用**分类式（模仿）或策略梯度**，不要用价值回归。
- 用搜索结果当价值目标时，必须检查它是「整局总回报」还是「剩余回报」。
- 每个新方法先在小样本上确认学习信号（相关系数、验证集一致率），再上大规模。
- 在线微调必须有「评估不超过起点就不保存」的保护，这次这个保护起了作用，没有污染最佳模型。

### 如果以后还想重试 DQN
需要同时满足这几个条件才值得：对所有合法动作都做评估（去掉 NaN）、用共同随机数降低比较噪声、只学相对优势（去掉绝对价值项）、在线阶段用与评估一致的贪心数据。当前没有计划重试。

## 2. 其他已发生的失败与局限

### F5 纯 PPO 从零（1196，对比方法 A 1230）
- 2000 轮约 1 小时；学到的策略不如参数化策略。【推测】原因：奖励稀疏且噪声大（单局 ±100），从零探索难以找到「攒法则再重衍」等需要多步协同的打法；参数化策略直接编码了这些结构。
- 教训：给 PPO 一个好的起点（蒸馏）比让它从零学强得多（1196 → 1267 → 1296）。

### F6 BC 试点欠训练（1077.8 → 放大后 1267）
- 试点只有 7.7 万条样本、450 次更新。放大到 2 万局专家数据、60 个轮次后升到 1267。【已验证】
- 教训：模仿学习对数据量和训练轮数很敏感，试点结果不能直接外推。

### F7 多候选补牌 ntri=4（无增益）
- 让专家对每个候选补牌方案各评估一次，只取最优。没有提升（在误差内）。【已验证】
- 【推测】原因：补牌方案间差距本来就小，多评估几个只增加噪声下的「赢者诅咒」，抵消了选择收益。

### F8 集成（+0.5）
- 四个检查点来自同一训练轨迹，高度相关，平均动作概率几乎没有多样性。【推测】
- 教训：集成需要不同初始化或不同训练路线的模型才有意义。

### F9 DAgger 几乎无增益（1267.0 → 1267.8）
- 学生在自己走到的状态上重新问专家，理论上能修正分布偏移，但这里增益很小。【推测】原因：BC 已经覆盖了大部分常见状态，且专家标签本身有模拟噪声，学生的误差主要来自标签噪声而不是分布偏移。
- 这也是计划改用更强专家（更多模拟、更好基础策略、噪声更低的比较）的依据。

### F10 PPO 微调进入平台期
- ft1 1290.4 → ft2 1292.4 → ft3 1295.8，每百轮只涨 1~2 分。【已验证】
- 【推测】到平台的原因：策略梯度的信噪比低（回报方差大、单步优势很小），而且已经逼近专家水平（约 1288~1297）。要继续涨，更可能需要更强的专家信号，而不是更多的 PPO 轮数。

### F11 搜索标签的交叉熵蒸馏（4 组超参，10 万局评估）
- 做了什么：用 ft4 当基础策略做网络引导搜索（k=3、R=512、改选门槛 4），采集 8 批共 4000 局、15.9 万条决策样本，其中改选 6845 条（4.3%）。搜索策略局均约 1308，比 ft4 纯网络高约 10。再用这些标签对 ft4 做加权交叉熵微调。
- 结果（10 万局，同种子）：权重 5、学习率 5e-5、3 轮：1297.71 → 1291.66（−6.05）；权重 1、2e-5、1 轮：+0.29；权重 2、1e-5、1 轮：+0.09；权重 1、5e-6、2 轮：+0.78。后三组都在误差内（单次评估的标准误 0.32，且并行评估的随机数不可复现，同一网络起点在不同次评估里在 1296.5~1297.7 之间波动）。
- 原因分析：
  1. 【已验证】激进设置会破坏网络：整体与标签一致率从应有的约 95.7% 降到 91%，改选样本上的一致率只有 20%~26%，也就是没学会改选，反而改坏了没被改选的状态。
  2. 【推测】搜索的 +10 来自约 4% 的决策上的**精细**改选，每次改选的收益有限且带噪声（门槛 4 附近的差距与模拟噪声同量级），只有 6845 条正样本，不足以让网络学会「在哪些状态改选」。
  3. 【推测】搜索的改选依赖对未来 R=512 次模拟的平均，是一种需要大量计算的「价值判断」，单次前向的网络很难拟合，这与 DQN 失败的原因类似（动作价值差距小、噪声大）。
- 教训：搜索可以直接当策略用（局均约 1308），但把它压回单个网络需要更多标签或更低噪声的标签，或者改用把搜索结果当 PPO 示范损失、或把搜索嵌入推理的方式。
- 评估方法的教训：并行评估无法复现，需要用同一次评估内的起点作对照，且小于约 1 分的差别不能当作提升。

## 3. 建模与工程层面的错误（已修复，留作提醒）

| 问题 | 后果 | 修复 |
|---|---|---|
| 把垣星效果误读为降低敌方防御 | 模型多了无关参数 | 用户纠正后，删除 d/λ |
| 策略只在放牌前评估法则 | 漏掉「先存法则、再重衍」等打法 | 重写，允许放牌之间打法则 |
| `pick_option` 的手牌上限误用 16 | 规则不一致 | 改用配置的 12 |
| pip 的 PyTorch 与 numba 的 libomp 冲突（OMP Error #15） | 无法同时运行 | 卸载 pip 版，装 conda-forge 版；未使用 `KMP_DUPLICATE_LIB_OK` |
| 图片太小看不清 | 规则可能读错 | 让用户重发 |
| Pages 部署失败 | 可视化页面不更新 | 启用 Actions 作为来源后重跑 |

教训：规则假设逐条确认、写进 `model_spec.md`；环境依赖冲突不要用环境变量绕过。

## 4. 仍未确认的风险

- （已解决 2026-11-20）重衍丢弃的法则会触发余波，用户确认并已实现；旧模型在新规则下几乎不变（1295.67），但旧规则下采集的搜索标签作废。
- 伤害数值公式会有一次大更新，届时所有结果需要用 `scripts/e_pipeline.py` 重跑；目前的数字只对当前规则成立。
- 所有评估都在同一套规则假设内，「最优」指的是对该模型最优。
